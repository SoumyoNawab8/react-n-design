# Plan: Replace Storybook with a Custom Site for react-n-design

## Goal
Build and deploy a new Vite-based SPA to replace the existing Storybook site on GitHub Pages. The new site will include:
1. An impressive **Landing Page** with interactive 3D parallax effects using the library's own neomorphic components
2. A **Components** showcase page (Ant Design-style) with live demos, code preview, and props documentation
3. A **Get Started** documentation page covering installation, theming, and usage

---

## Architecture Overview

### Site Directory
Create a `site/` directory in the repo root. It will be a standalone Vite SPA that imports components directly from `../src/components/*` (dogfooding).

```
site/
  index.html              # Entry HTML
  vite.config.ts          # Vite SPA config with base: '/react-n-design/'
  tsconfig.json           # Extends root tsconfig
  src/
    main.tsx              # React DOM root mount
    App.tsx               # react-router-dom routes
    pages/
      Home.tsx            # Landing page (3D hero, features, footer)
      ComponentsPage.tsx  # Components list + detail view
      GetStarted.tsx      # Installation, theming, usage guides
    components/
      Layout.tsx          # Header, sidebar nav, footer, theme toggle
      Hero3D.tsx          # @react-three/fiber floating neomorphic shapes
      ComponentCard.tsx   # Grid card for component listing
      ComponentDemo.tsx # Live demo + controls for a single component
      PropsTable.tsx      # Auto-generated props table from TS
      CodePreview.tsx     # Syntax-highlighted code block
      ScrollReveal.tsx    # Framer Motion scroll animation wrapper
    data/
      components.ts       # Component metadata (name, category, description)
      componentProps.json # Generated by react-docgen-typescript
      getStarted.md       # Get Started markdown content
    styles/
      global.css          # Site-specific styles, 3D transforms
```

### Tech Stack
- **Vite** (leverages existing dev toolchain)
- **react-router-dom** (SPA routing; not currently installed)
- **@react-three/fiber + @react-three/drei** (3D floating neomorphic shapes in hero)
- **framer-motion** (already peer dep — scroll animations, page transitions)
- **styled-components** (already peer dep — consistent with library)
- **react-docgen-typescript** (build-time prop extraction into JSON)
- **prismjs** or library's own `CodeBlock` (syntax highlighting)

### Routing Strategy
Since this is a SPA deployed to GitHub Pages under a project path (`/react-n-design/`), we need:
- `HashRouter` OR `BrowserRouter` + a `404.html` redirect trick
- **Decision: Use `BrowserRouter`** with a `404.html` page that redirects to `index.html` with the path preserved (standard GitHub Pages SPA pattern)

Routes:
- `/` → Home (Landing)
- `/components` → Components list
- `/components/:name` → Individual component docs
- `/get-started` → Get Started docs

  - **Navigation**: Breadcrumbs, Tabs, Steps, Stepper, Pagination, Menu, AppBar, CommandPalette, FloatButton, SkipToContent
  - **AI / Chat**: AIChat, PromptInput, PromptBuilder, ModelSelector, ToolCallCard, SuggestionChips, MentionInput, DiffViewer
  - **Other**: Form, ComboBox, MultiSelect, Segmented, Toggle, CopyButton, CodeBlock, GradientBorder, Collapsible, VisuallyHidden

**Main Content Area (per component)**
1. **Header**: Component name + short description
2. **Live Demo**: Render the actual component with a control panel (using a simple form of argTypes — map props to input types)
3. **View Code** toggle: Show the component source `.tsx` file in a `CodeBlock`
4. **Props Table**: Generated from `componentProps.json`
   - Prop name, Type, Default, Required, Description
5. **Examples**: Pre-built examples showing common use cases (can reuse story logic)

**Props Extraction Strategy**
- Add a script `scripts/gen-component-docs.ts` that uses `react-docgen-typescript` to parse all `src/components/**/*.tsx` files and output `site/src/data/componentProps.json`
- Run this as a pre-build step: `"gen:docs": "tsx scripts/gen-component-docs.ts"`

## Phase 5: Build & Deployment

1. **Update `package.json` scripts**
   - Add `"build:site": "npm run gen:docs && vite build --config site/vite.config.ts"`
   - Add `"gen:docs": "tsx scripts/gen-component-docs.ts"`
   - Add `"preview:site": "vite preview --config site/vite.config.ts"`

2. **Update `vite.config.ts` in site**
   - `base: '/react-n-design/'`
   - `outDir: '../storybook-static'` (or a new dir, see below)

3. **Create `site/public/404.html`**
   - Standard GitHub Pages SPA redirect: capture path, redirect to `index.html` with path in query string, then `App.tsx` reads and navigates

4. **Update GitHub Action `.github/workflows/deploy-storybook.yml`**
   - Rename file to `deploy-site.yml` (or keep name for simplicity)
   - Change build step from `npm run build-storybook` to `npm run build:site`
   - Keep artifact path as `./storybook-static` to minimize changes

5. **Test locally**
   - `npm run build:site`
   - `npm run preview:site`

## Trade-offs & Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Router | `BrowserRouter` + `404.html` | Cleaner URLs than HashRouter; standard GH Pages SPA pattern |
| 3D Library | `@react-three/fiber` | Native React 3D; integrates well with framer-motion; impressive visuals |
| Props Extraction | `react-docgen-typescript` | Automated, reliable for TS components; one-time build script |
| Component Imports | Direct `../src/` imports | Dogfoods the library; no need to publish/build first |
| Build Output | Reuse `storybook-static` | Minimizes workflow changes; GitHub Pages already configured |
| Styling | styled-components + CSS | Consistent with library; CSS for 3D/animation-specific styles |

## Risks & Mitigations

1. **Build size**: @react-three/fiber adds ~100KB. Mitigation: lazy-load the 3D canvas with `React.lazy()` and `Suspense` on the home page.
2. **GitHub Pages SPA routing**: The `404.html` redirect trick is well-established and reliable.
3. **TypeScript strictness**: The library build uses `--noEmitOnError false`. The site build should be equally forgiving or use its own tsconfig.
4. **Component source code display**: Importing `.tsx` files as strings requires `?raw` Vite imports. We'll use `import source from '../src/components/Button/Button.tsx?raw'` pattern.
